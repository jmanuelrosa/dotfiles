# Skill precedence


[roles/ai/files/claude/rules/skill-precedence.md](../../roles/ai/files/claude/rules/skill-precedence.md) is the second always-on rule, and it exists because the craft skills the seats route to carry roughly ten live contradictions against those seats' own failure-mode references, on ordinary briefs rather than edge cases. `emil-design-eng` prescribes `framer-motion` past an ask-first gate, an `:nth-child` stagger against "never positional selectors", and a hover `scale(1.05)` against "state styles change paint, not geometry"; `frontend-design` makes "4-6 named hex values" the deliverable against "no raw value beside the token system". Left unstated, the agent resolves each silently, which is how a seat whose first hard rule is "never trade accessibility for aesthetics" ends up taking its review format from a checklist with no accessibility rows in it.

Two tiers, and the split is the point. **Tier 1 is absolute: no skill grants permission**, so a prescribed dependency, scale step, brand-surface change, or parallel token system is a `needs-decision`, never an edit, because an ask-first gate exists to route a decision to a human and a skill in the context window is not one. **Tier 2 is defeasible: a reference's `Check:` is the default, and a skill may override it only by naming the check it trades against and satisfying it another way** in the report. A blanket tier-1 rule for everything would ban `clip-path` reveals and hover scale outright, which removes the technique depth that is the only reason to load emil at all.

Outside both tiers, **a skill never sets an output contract**. Some carry harness control flow rather than advice: emil's `:10-14` tells a first invocation to emit a canned greeting and stop, and its `:40` mandates a Before/After table with a "never do this" counter-example. Inside a delegated agent the first returns a greeting where the caller expected work, and the second collides with a completion report contract on the common path. Both are void, named in the rule by file so the ban is checkable.

It lives in `rules/` rather than in each agent for the reason `code-review.md` does: it is cross-seat, it is equally the bar for *writing* against a skill as for reviewing one, and four copies would drift. The Ansible task globs `files/claude/rules/*.md`, so it needed no play change.
